0. 结论摘要

  1. 功能与安全边界扎实，界面结构没有跟上功能增长。 预览、确认、撤销、事务式编辑、锁定清草稿等边界都已实现，但界面仍是"单列卡片 + 每个功能追加一个 section"。v1.3 信息架构规定的 5 个固定入口已变成顶部 7 个同级按钮；"安全与恢复"一页在 1280×800 下高 2747px，含 11 个标题、15 个按钮。
  2. 最高频的日常任务路径太长。 点击条目直接进入编辑表单，没有只读详情；验证码在"更多选项"里，展开后位于页面约 1479px 处，还要再点"显示验证码"。在 Tauri 默认窗口 1000×700 下，密码列表从 y=301px 开始，只能完整显示 4 行。
  3. 按钮层级失效。 密码页一屏同时有 7 个实心主色按钮（每行一个"复制密码"）；编辑已保存条目时，最醒目的控件是"生成密码"；连接页 4 个可选外部服务各有一个主按钮，而浏览器扩展排在它们下面。
  4. 有几处状态显示与实际不符。 没有配置任何同步时，9/9 条目都显示"等待同步"；第一次写入后"尚未设置备份"提醒就消失了（因为自动恢复备份被计入了备份数），但安全页同时显示"最近一次成功备份：尚未备份"；安全状态摘要无论状态如何都是绿色"成功"底色。
  5. 中英文没有对齐。 中文界面输错主密码时显示英文 Invalid password or vault；首次启动默认中文，首启页和解锁页都没有语言切换；<html lang="en"> 写死不变；源码中约 779 处内联 zh ? … : … 文案，而走 t() 字典的只有 131 处；"保险库/密码库"两种叫法混用（20/26 处）；扩展里同一条提示的中英文内容不一致。
  6. 视觉系统有设计令牌，但已经漂移。 后加的组件写死数值；.card h3 的选择器优先级覆盖了 .section-title，导致英文分区标题变成 16px 全大写；输入框边框对比度只有 1.5–1.6:1（WCAG 1.4.11 要求 ≥3:1）；主按钮 hover 状态白字对比度 4.03:1；"跳到主内容"链接在未聚焦时露出 4.6px 的蓝条。
  7. 建议方向：采用 Windows 原生风格（参照 Fluent）的"左侧导航 + 列表/详情"桌面结构（方向 A）。分三步落地：先修语义与可访问性缺陷（不动结构），再建立令牌和基础组件，最后重排结构。全程不改数据格式，不改安全边界。

3. 参考矩阵

选取标准：与"Windows 本地优先个人密码管理器 + 浏览器扩展"的任务流直接相关。所有来源的访问日期均为 2026-10-21。社区帖子只作为用户反馈旁证，不作为产品事实。

R-01 1Password for Windows：主窗口三栏，查看与编辑分离

  • 界面/交互：侧栏（Favorites、tags、Watchtower、Archive、Recently Deleted）→ 条目列表（分类筛选 + 搜索）→ 选中后显示详情（只读）；Edit（Ctrl+E）进入编辑，Save（Ctrl+S）保存；右上角锁定按钮（Ctrl+Shift+L）。
  • 来源：https://support.1password.com/getting-started-windows/
  • 值得学习：浏览与编辑是两种状态；收藏、归档、最近删除作为一级筛选，而不是下拉框里的"位置"。
  • 对应问题：G-03、G-04、E-01、L-03。
  • 如何适配：左侧导航中，"密码"下设 全部/收藏/标签/归档/回收站；中栏为列表，右栏为只读详情；Ctrl+E 编辑、Ctrl+S 保存、Esc 取消（编辑时仍走现有的 pendingAction 脏数据确认）。
  • 取舍/不要照搬：多账户/多集合切换器与 VU 的单个本地库无关；不要复制它庞大的条目分类，VU 只需要现有的 5 个可新建类型加上兼容类型。

R-02 1Password Quick Access：系统级快速搜索

  • 界面/交互：Windows 默认快捷键 Ctrl+Shift+Space，也可从托盘打开；选中条目后的省略号菜单提供复制用户名/密码；"Open Item In New Window"；Esc 取消。
  • 来源：https://support.1password.com/quick-access/ （另见社区帖 https://www.1password.community/discussions/1password/how-can-i-change-shortcuts-in-quick-access-/90913 ，用户反映可修改的快捷键有限，仅作旁证）
  • 值得学习：一个窗口里集中处理"找到 → 复制/打开"；每个条目的动作集中在一个菜单里，并配有快捷键。
  • 对应问题：Q-01、Q-02、Q-04。
  • 如何适配：快捷搜索结果改为单行；Enter 的主动作随条目类型变化；Tab 打开动作列表（见 R-10）；在设置里提示 Ctrl+Shift+Space 可能与 1Password 冲突。
  • 取舍/不要照搬：1Password 选中条目会"打开网站并填充"。VU 的安全模型是不自动提交、auto-type 要先确认目标窗口，所以 Enter 不应打开网站或自动输入。

R-03 1Password Watchtower：问题分组 + 条目上的提醒横幅

  • 界面/交互：按问题类型分组（compromised、vulnerable、weak、reused、unsecured websites、2FA 等），每组有建议动作；有问题的条目"在整个 1Password 中显示提醒横幅"。
  • 来源：https://support.1password.com/watchtower/
  • 值得学习：健康检查的结果回流到条目本身。
  • 对应问题：S-03、S-05。
  • 如何适配：详情页对弱密码或重复密码显示 warning 级 InfoBar（"弱密码 · 与 1 个账号重复 [去网站修改] [更新已存密码]"）；列表增加"需要处理"筛选；安全概览卡片显示计数。只使用现有 api.passwordHealth() 的本地结果，不增加网络请求。
  • 取舍/不要照搬：需要在线数据的类别（例如"网站支持 2FA"）与 VU 的离线默认冲突；泄露查询保持"本次访问单独同意"的现状。

R-04 Bitwarden 浏览器扩展：自动填充与输入框内菜单

  • 界面/交互：Vault 页顶部 Autofill suggestions，点击条目即填充，查看要单独点 View；输入框内菜单（Show autofill suggestions on form fields），Esc 关闭；网址不匹配时提供 Autofill and add this website / Autofill without adding the website；默认在填充后自动复制 TOTP（Copy TOTP automatically）。

  • 取舍/不要照搬：默认自动复制 TOTP 会增加剪贴板暴露，VU 已有显式的"填入验证码"，最多作为可选项；Bitwarden 默认按 Base domain 匹配，VU 默认精确主机是有意设计，应保留。

R-05 Bitwarden Vault Health Reports：泄露结果的措辞

4.1 三个候选方向

A. Windows 原生工作台（推荐） B. 深色保险箱精修 C. 键盘优先命令中心

4.2 推荐：A；B 的令牌整理作为第一阶段；C 的动作列表放进快捷搜索

结合用户与任务的理由 1. 用户：Windows 上的个人用户，IA 文档明确以"不了解密码管理器实现的新手"为默认对象；不少人会从 Chrome/Edge、Bitwarden、KeePassXC、Proton Pass 迁移过来（VU 已支持这些导入或连接）。列表/详情是这些产品共同的心智模型（R-01、R-06、R-07），迁移用户不必重新学习。 2. 任务频率： - 每天：找到 → 复制/填充 → 偶尔看验证码。需要列表常驻、详情即看即复制。 - 每周：整理、改密码、处理健康问题。需要批量模式，以及问题回流到条目。 - 很少但关键：备份、恢复、换机、同步配置、分享。需要清晰的结构、预览与确认，不能和日常操作挤在一起。 - 方向 A 按频率分层：日常操作在"密码"的双栏里完成；低频高风险操作进入"安全与恢复/连接/分享"的概览和子页，每一步保留现有的预览与确认。 3. 平台一致：产品只支持 Windows，并深度集成 Hello、托盘、全局快捷键与 auto-type，采用 Windows 的排版、导航与对话框约定能降低陌生感。 4. 中英文：方向 A 的组件化（Button/Field/Dialog/InfoBar）是把约 779 处内联文案收进字典的自然切入点；固定宽度的设置卡片和图标按钮能减少英文变长造成的换行。 5. 架构可行：全部基于现有 React + CSS 变量实现，不引入 UI 框架，不改 API 与数据格式。唯一可能新增的资源是图标（建议直接内置 SVG，见 4.3.6）。

4.3.9 其他组件

  • Menu：替换 <details>。role="menu"，支持方向键、Home/End，Esc 关闭并把焦点还给触发按钮，点击外部关闭，同时只开一个。
  • SegmentedControl：替换首启页的"创建/恢复"切换，使用 role="radiogroup"。
  • SettingsCard：左边标题 + 一行说明，右边控件（Toggle/Select/Button），控件最大宽度 280px。
  • Toggle switch：用于立即生效的设置（托盘、启动时检查更新）；复选框只用于需要提交的表单。
  • Stepper：一次只有一个当前步骤，aria-current="step"，步骤数 ≤4。
  • EmptyState：图标 + 一句话 + 一个主动作；空列表时隐藏页头的"添加"或降为次要，避免两个相同的主按钮。

7.4 测量指标

  • 任务完成：独立完成 / 有提示后完成 / 失败；记录每次提示的原文。
  • 耗时：从任务说明结束到达成成功标准；报告中位数和范围，样本少时不报告均值。
  • 错误：点错入口、误触危险操作入口（打开了确认框又取消）、误改数据（打开编辑后需要放弃更改）、复制错字段。

  • 理解度（开放式问题，按预设要点评分）：
  • "'等待同步'是什么意思？现在需要你做什么吗？"

  • "这个分享链接被打开过之后，你还能撤回吗？"
  • "扩展会帮你点'登录'吗？"
  • 结束问卷：SUS（不修改题目与计分），与 v1.3 计划保持一致。
